# RATIONALE — 为什么这样设计

> 本文件解释"为什么路由"以及"为什么外部路由"（设计依据）。
> 数据来自上游 dsh-router-standard @9727510 的实测（DeepSeek V4 Pro /
> V4 Flash，官方 API，21 点探针 n=2，reasoning_effort=max）。
> 只想装来用的话可以跳过本文件——README 已经足够。

## 1. 三带：模型行为不是连续谱

模型沿 react↔spec 轴的行为**坍缩为三个稳定区**，而非连续谱：

| band | 模式区间 | 实测行为 |
|---|---|---|
| `spec` | 0 – 0.19 | 稳定计划型（`We` 轨迹，let-me ≈ 0） |
| `mixed` | 0.2 – 0.49 | **过渡陷阱**：`We`/`The`/`Let` 不稳定混合 |
| `react` | 0.5 – 1.0 | 稳定执行型（`The`/`Let` 第一人称，we ≈ 0）——11 个模式值行为一致 |

V4 Flash 是阈值型（0–0.5 全在 spec 侧，0.75+ 才跳变）。所以"连续微调模式"在
模型层是幻觉——**量化为三带才是诚实接口**。

## 2. persona 是主导触发器，工具面是次要

- 同一模型：spec 条件下维护基准 Project2 minimal 99/96，react 条件下
  greenfield 构建 Mario 10/10；**错配**则分别为 91 / 6——仅靠 prompt 条件，
  约 10 分摆动。
- 一句话 persona 切换就能翻转轨迹；工具 schema 面是次要条件；目录文本放进
  user 消息无效。
- **行为路径提交**：一旦锚定，之后扩展开工具目录只扰动至多一个推理块，永不翻转
  模式。

## 3. 模型不能自路由——必须外部路由

P3/P5/P8 显示：模型内部自路由窗口很小，只有 WEAK persona + few-shot 路由指令
（lean 不翻转）可用。会话中途没有切换模式的奖励信号，且行为相位跃迁意味着
模型在首个请求就提交。**模式选择必须来自外部**——人或启发式分类器或学习型
路由器。本插件就是那个自动化的外部路由器。

## 4. 弱带按模型选 persona（P11/P24/P23）

| 模型 | 最优弱 persona | 实测 |
|---|---|---|
| DeepSeek V4 Pro | WEAK_PRO（spec 句 + classify 指令，无锚） | 100% 路由 |
| DeepSeek V4 Flash | WEAK_FLASH（+ recall/anti-runaway 锚） | 96% 路由；单任务完成率 100% |

插件读会话模型自动选择，无需配置。

## 5. 近场引导（深度自适应）

每条用户消息后，弱带会话注入一条引导，按任务复杂度分流：

- **简单任务** → 快速收敛引导（1 步，零浪费）
- **复杂任务**（>120 字或含架构关键词）→ 决策闭合深引导：深入架构/边界/集成点，
  不在环境/工具上耗推理；信息完备再产出；每个推理块以"决策或信息需求"收尾
  （深度 +12% 且收敛更快，3/3 完成）。

反跑锚（anti-runaway）抑制环境怀疑/重复确认：实测占推理 token 的 0.0–0.3%。

## 6. 首条消息为什么关键

首轮 system prompt 与工具 schema 锚定模型以什么方式对待任务。会话轨迹早期定型，
所以路由必须在首个模型请求前注入 persona + 首轮核心工具集。锚定后恢复完整工具面，
什么都不永久放弃；模式由持久化 session 事件派生，resume/reload 保持。
